D-2026-09-27-tray-app-1 (2026-09-27): O popup do tray NÃO usa `<select>` nativo — o seletor de monitor, a predefinição de cor e as features NC de "Todos os ajustes" passam a ser um dropdown próprio renderizado DENTRO da página (botão + lista `role="listbox"`/`option`, padrão ARIA "select-only combobox": Enter/Espaço/Alt+↓ abre, ↑/↓/Home/End navegam, Enter confirma, Esc fecha sem mudar, clique fora fecha, foco volta ao botão), com os mesmos tokens visuais dos cartões. Motivo — bug reportado pelo usuário testando a versão instalada ("sempre que eu seleciono um select list o painel fecha"): no Linux o WebKitGTK abre o menu do `<select>` como uma janela GTK separada; a janela do popup perde o foco, recebe `WindowEvent::Focused(false)` e se esconde (D-2026-09-26-tray-app-5: esconde ao perder o foco). No Windows o `<select>` do WebView2 também abre uma janela de popup própria. Um dropdown in-page elimina a janela nativa nos dois SOs e mantém o visual consistente. A regra "esconde ao perder o foco" continua valendo para cliques fora do app. Decidido pelo orquestrador do `/jdi-issue` a partir do feedback do usuário (iter 3 do loop).
