D-2026-09-28-release-packaging-3 (2026-09-28): Extensão retrocompatível de `qualidade.yml` no `github-workflows` — empacotar Tauri e binários extra.

Três campos novos no componente rust, todos opcionais, compatíveis com a forma de `so`/`pacotes_sistema`/`auditoria`/`build_release` já existente (D-2026-09-27-ci-crossbuild-2/-3): sem eles, o componente roda exatamente como hoje.

- **`empacotar_tauri`** (boolean, default `false`): exige `linguagem: rust` e `build_release` preenchido com o MESMO pacote que será empacotado — o passo reaproveita o binário que `build_release` acabou de provar que compila, nunca compila de novo por fora do `cargo tauri build`.
- **`caminho_tauri`** (string, obrigatório quando `empacotar_tauri: true`): diretório do `tauri.conf.json` relativo à raiz do checkout (aqui: `apps/ddc-tray/src-tauri`) — necessário porque o componente `rust-linux`/`rust-windows` roda com `caminho` vazio (workspace inteiro, `--workspace`), e o `tauri.conf.json` não vive na raiz.
- **`binarios_extra`** (string, default `""`): lista de pacotes do workspace, separados por espaço, para compilar em release e empacotar como arquivo baixável — aqui, `"ddc-cli"`.

Passos novos no job `qualidade` (rust), depois de `Build <pacote> (release)`, todos com `working-directory: .` (path absoluto do checkout, não o `caminho` do componente):

1. **`Build binarios extra (release)`** (`if: matrix.c.linguagem == 'rust' && matrix.c.binarios_extra`): `for p in $BINARIOS_EXTRA; do cargo build -p "$p" --release --locked; done` (variável por `env`, nunca interpolada no `run:`).
2. **`Empacotar binarios extra`** (mesmo `if`): monta `dist/<pacote>-<alvo>.tar.gz` no Linux (`tar czf`, conteúdo = binário + `LICENSE`) ou `dist/<pacote>-<alvo>.zip` no Windows (`zip`, mesmo conteúdo) — `<alvo>` é o mesmo par que `cargo-llvm-cov`/`cargo-audit` já calculam por `$RUNNER_OS-$RUNNER_ARCH` (`x86_64-unknown-linux-gnu` / `x86_64-pc-windows-msvc`), reaproveitado sem duplicar a tabela.
3. **`Instalar tauri-cli`** (`if: matrix.c.linguagem == 'rust' && matrix.c.empacotar_tauri`): binário pronto, versão fixa e sha256 conferido — mesmo argumento e mesmo padrão de `cargo-llvm-cov`/`cargo-audit` (D-2026-09-27-ci-crossbuild, `qualidade.yml`): baixar o `.tar.gz`/`.zip` da release do `tauri-cli` no GitHub para o alvo do runner, conferir o hash, extrair para `${CARGO_HOME}/bin`. Nunca `cargo install tauri-cli` (minutos de compilação, versão do dia do crates.io).
4. **`Empacotar <pacote> (Tauri)`** (mesmo `if`, nome via `format()` como em `build_release`): `cd "$CAMINHO_TAURI" && cargo tauri build --locked --bundles "$BUNDLES"`, onde `BUNDLES` é calculado dentro do próprio passo por `$RUNNER_OS` (`deb,rpm,appimage` no Linux; `msi,nsis` no Windows) — não é um campo novo, porque o conjunto de bundlers válidos já é 1:1 com o SO do runner.
5. **`Guardar pacotes`** (`if: matrix.c.linguagem == 'rust' && (matrix.c.empacotar_tauri || matrix.c.binarios_extra)`): `actions/upload-artifact@<sha do lock>`, `name: pacotes-${{ matrix.c.nome }}` (contrato de nome que `lancar.yml` consome via `artefatos: "pacotes-*"`, D-2026-09-28-release-packaging-2), `path` cobre `${{ matrix.c.caminho_tauri }}/target/release/bundle/**/*.deb`, `*.rpm`, `*.AppImage`, `*.msi`, `*.exe` (o instalador NSIS; o binário cru de `ddc-tray` não é publicado, só o instalador) e `dist/*`, `if-no-files-found: error` (empacotamento ligado tem de produzir algo, silêncio é falha).

O `Cache do target` (já existente) continua igual — `cargo tauri build` reusa o mesmo `target/` do `cargo build`/`cargo llvm-cov` anteriores no mesmo job, sem cache adicional.
