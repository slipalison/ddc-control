D-2026-09-25-core-domain-3 (2026-09-25): `risk_for_code(code: VcpCode) -> Risk` no core usa uma tabela seed hardcoded — exatamente a classificação já documentada no specialist `jdi-doer-ddc-control` (seção Monitor-write safety): Safe = {0x10, 0x12, 0x14, 0x16, 0x18, 0x1A, 0x62, 0x87, 0xCC}; Dangerous = {0x04, 0x05, 0x06, 0x08, 0x60, 0xCA, 0xD6} ∪ {code >= 0xE0}. Qualquer código fora dessa tabela seed (ex.: 0x02, 0x0B, 0x0C, 0x52, 0xAC, 0xAE, 0xB2, 0xB6, 0xC6, 0xC8, 0xDF, 0xFD, 0xFF — presentes no caps real do "RTK QHD HDR" — ou qualquer código ainda não sondado) tem `Risk` default = `Dangerous`. Rationale: prioridade 1 é segurança (CLAUDE.md) — fail-safe: até o catálogo completo da phase `full-osd-control` classificar cada código individualmente, um código desconhecido exige `Confirm::Yes` para escrita em vez de assumir que é seguro. Este default nunca bloqueia leitura, só escrita (ver D-2026-09-25-core-domain-4).
