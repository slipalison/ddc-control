D-2026-09-25-cli-2 (2026-09-25): Seleção de monitor quando `--monitor` é omitido: `enumerate()` roda (sem sondar DDC — D-2026-09-25-ddc-backends-4) e (a) exatamente 1 monitor → é usado automaticamente, sem flag necessária; (b) 0 monitores → erro "nenhum monitor encontrado" (código de saída de not-found, D-2026-09-25-cli-5); (c) 2+ monitores → erro que lista os ids encontrados (mesmo formato de `ddc-cli list`) e instrui a passar `--monitor <id>` — a CLI NUNCA escolhe um monitor "provável" entre vários (prioridade 1 do CLAUDE.md é segurança; adivinhar entre 2+ telas antes de um `set` seria a categoria de erro mais cara possível). Quando `--monitor <valor>` é passado, o casamento tenta, nesta ordem: (1) igualdade exata com o `MonitorId` (a string que `list` imprime); (2) um índice 1-based na ordem devolvida por `enumerate()` (a mesma numeração que `list` mostra), quando `valor` é só dígitos; (3) uma substring case-insensitive única do id — se mais de um id contém `valor`, erro listando os candidatos; se nenhum contém, `DdcError::MonitorNotFound`.

Rationale: replica o padrão já conhecido do `ddcutil --display N`, mas usa o `MonitorId` estável (D-2026-09-25-ddc-backends-2) como fonte de verdade em vez de só índice — que desloca no hotplug (regra já registrada no specialist doer). O índice é só uma conveniência de digitação que reflete a MESMA ordem de `enumerate()` que o backend já produz, nunca uma identidade paralela guardada pela CLI.
